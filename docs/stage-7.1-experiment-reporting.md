## Short summary

The current run artifact is intentionally compact, but it hides the most important experiment internals: generated prompts, model responses, AKG decision flow, and diagnostic context when a run fails or converges too early. This plan adds a non-breaking rich-reporting layer via sidecar artifacts (`.rich.json`, `.events.jsonl`, `.failure.json`), while preserving the existing `stage6.v1` run JSON contract and CLI behavior. It also addresses the low Gemini module coverage issue by introducing a coverage-oriented orchestration mode, stricter decision validation, and explicit quality diagnostics.

## Design & architecture

### 1) Problem decomposition

Current gaps against requested features:

1. Prompt generated by algorithm: currently transient in `state.messages`, not persisted into run artifact.
2. AI response in workflow: same issue, not persisted as explicit trace.
3. AKG traversal: only implicit via final state (`confirmed_vulns`, `current_chain`), no per-step traversal event log.
4. Rejection vs success messages: only guardrail counts/snippets exist; success events are not normalized.
5. Failure logging file: only `artifact.error` string exists, no dedicated failure artifact.
6. Gemini “bad results”: orchestrator currently short-circuits to scorer on high-impact outcomes (`admin_session_obtained`), causing low breadth coverage.

### 2) Root-cause analysis for low Gemini coverage

The sample run stops at 3 iterations and exits after reaching `admin_session_obtained`. With the current stop logic, this is expected behavior in impact-first mode and is **not purely model quality**. Coverage in that run is:

$$
\text{coverage} = \frac{|\{m \in \text{MODULES} : \text{score}(m) > 0\}|}{12} = \frac{2}{12} = 16.7\%
$$

So the main problem is policy/observability, not just provider choice.

### 3) Proposed architecture (non-breaking)

Keep `stage6.v1` primary artifact untouched; add sidecars:

1. `results/runs/{run_id}.rich.json`
   - Structured summary of prompt/response traces, AKG traversal summary, rejection/success message indexes, and diagnostics pointers.
2. `results/runs/{run_id}.events.jsonl`
   - Append-only per-step event stream for deterministic replay.
3. `results/runs/{run_id}.failure.json`
   - Written only when run status is `error` or diagnostic hard-failure.

This preserves backward compatibility while enabling deep analysis.

**Compatibility rule:** do not add new top-level keys to the primary Stage 6 run artifact while `schema_version` remains `stage6.v1`. All enriched data lives in sidecars.

### 4) Telemetry event model

Each event entry (JSONL line) uses deterministic ordering with `seq`:

```json
{
  "seq": 17,
  "ts": "2026-04-17T16:22:01.336Z",
  "iteration": 4,
  "node": "orchestrator",
  "event_type": "orchestrator.llm.response",
  "status": "ok",
  "payload": {
    "provider": "gemini",
    "prompt_hash": "sha256:...",
    "response_text": "{\"next_agent\":\"sqli_agent\"}",
    "parsed_next_agent": "sqli_agent",
    "fallback_used": false
  }
}
```

Event types (minimum):
- `orchestrator.prompt.generated`
- `orchestrator.llm.response`
- `orchestrator.guardrail.rejection`
- `orchestrator.fallback.applied`
- `akg.viable_paths`
- `akg.route.selected`
- `agent.outcome.success`
- `agent.outcome.partial`
- `agent.outcome.error`
- `run.failed`

### 5) AKG traversal capture strategy

To capture routing decisions from chain routing (currently in a pure conditional function), introduce a router node pattern:

- Add `chaining_router_node(state) -> dict` in `core/chaining_coordinator.py`.
- It computes route + emits `akg.route.selected` event + sets `next_agent`.
- `core/graph_builder.py` routes `agent -> chaining_router -> conditional(next_agent)`.

This preserves decision semantics and enables traceable AKG traversal logging.

### 6) Rejection and success message model

Normalize message events into two explicit classes:

- Rejection message events:
  - source: guardrail/refusal/policy parse failure
  - payload: `provider`, `context`, `snippet`, `reason_code`
- Success message events:
  - source: agent confirmation and chain progression
  - payload: `module`, `score_before`, `score_after`, `confirmed_added`, `outcomes_added`

### 7) Failure logging system

On run failure, write:

- `results/runs/{run_id}.failure.json` (structured diagnostics)
- optional plain text mirror: `results/runs/{run_id}.failed.log`

The CLI should print pointer paths when present:
- `Failure artifact written: ...`
- `Failure log written: ...`

### 8) Gemini quality remediation plan

Add orchestration policy controls:

- `stop_policy`: `impact` (current behavior) or `coverage` (new)
- `coverage_target`: float in `[0,1]` (default 0.70 for experiments)

In `coverage` policy:

1. Do not stop immediately on first high-impact outcome.
2. Continue until coverage target reached or budget exhausted.
3. Add anti-convergence rule (avoid repeating same chain when no new progress for 2 iterations).
4. Expand prompt context to include:
   - unattempted modules
   - recent decision streak
   - progress delta
5. Add one-shot response repair on invalid JSON before deterministic fallback.

Also make model config explicit for experiments:
- recommend configurable model selection (`gemini-3-flash-preview` vs stronger Gemini model) without hardcoding.

## Files to create

### 1) `evaluation/telemetry.py`

**Purpose:** event schema + buffer + JSONL writer for run telemetry.

**Patch snippet (new file):**

```python
from __future__ import annotations

from dataclasses import dataclass, asdict
from datetime import datetime, timezone
from pathlib import Path
from typing import Any
import json
import hashlib


def utc_now_iso() -> str:
    return datetime.now(timezone.utc).isoformat()


def stable_sha256(text: str) -> str:
    return "sha256:" + hashlib.sha256(text.encode("utf-8")).hexdigest()


@dataclass(slots=True)
class TelemetryEvent:
    seq: int
    ts: str
    iteration: int
    node: str
    event_type: str
    status: str
    payload: dict[str, Any]


class RunTelemetry:
    def __init__(self, run_id: str):
        self.run_id = run_id
        self._seq = 0
        self.events: list[TelemetryEvent] = []

    def emit(self, *, iteration: int, node: str, event_type: str, status: str, payload: dict[str, Any]) -> None:
        self._seq += 1
        self.events.append(
            TelemetryEvent(
                seq=self._seq,
                ts=utc_now_iso(),
                iteration=iteration,
                node=node,
                event_type=event_type,
                status=status,
                payload=payload,
            )
        )

    def write_jsonl(self, path: Path) -> Path:
        path.parent.mkdir(parents=True, exist_ok=True)
        with path.open("w", encoding="utf-8") as handle:
            for event in self.events:
                handle.write(json.dumps(asdict(event), sort_keys=True) + "\n")
        return path
```

```python
from typing import Any
import json


def write_failure_artifact(
    *,
    output_dir: Path,
    run_id: str,
    error: str,
    final_state: dict[str, Any],
    recent_events: list[dict[str, Any]],
) -> Path:

    payload = {
        "schema_version": "stage6.failure.v1",
        "run_id": run_id,
        "error": error,
        "final_state": final_state,
        "recent_events": recent_events,
    }
    path = output_dir / f"{run_id}.failure.json"
    path.write_text(json.dumps(payload, indent=2, sort_keys=True), encoding="utf-8")
    return path
```

### 3) `evaluation/diagnostics.py`

**Purpose:** quality diagnostics and low-coverage root-cause hints.

**Patch snippet (new file):**

```python
from __future__ import annotations

from core.state import MODULE_NAMES


def module_coverage_ratio(scores: dict[str, int]) -> float:
    covered = sum(1 for name in MODULE_NAMES if int(scores.get(name, 0)) > 0)
    return covered / len(MODULE_NAMES)


def diagnose_quality(*, scores: dict[str, int], total_iterations_used: int, highest_outcome: str | None) -> dict:
    coverage = module_coverage_ratio(scores)
    reasons: list[str] = []
    if coverage < 0.4:
        reasons.append("low_module_coverage")
    if total_iterations_used <= 3:
        reasons.append("early_termination")
    if highest_outcome in {"admin_session_obtained", "rce_achieved"} and coverage < 0.4:
        reasons.append("impact_before_coverage")
    return {"coverage_ratio": coverage, "flags": reasons}
```

## Backwards compatibility and migration steps

1. Preserve existing primary artifact structure and `schema_version: stage6.v1`.
2. Add rich data only through sidecars and optional fields.
3. Keep old `route_after_agent(state)->str` for test compatibility.
4. Default behavior remains impact-first unless config/CLI overrides for coverage experiments.
5. Update formatters to degrade gracefully when sidecars are absent.

## Error handling and edge cases

1. Missing prompt/response due provider error:
   - emit `orchestrator.llm.response` with `status=error` and `reason_code`.
2. Invalid JSON response from model:
   - one repair attempt; then deterministic fallback.
3. Sidecar write failure:
   - run should still return primary artifact; append warning in `diagnostics`.
4. Large response bodies:
   - store truncated text + hash to avoid oversized artifacts.
5. Sensitive content in logs:
   - redact API keys/tokens before writing events.

## Rollback plan and failure-mode handling

1. Disable enriched reporting flag in config/CLI (feature off).
2. Revert graph router node change and return to direct conditional edges.
3. Keep sidecar writers isolated so core run path still works if telemetry modules are reverted.
4. If coverage policy causes regressions, revert to `stop_policy=impact` while retaining telemetry-only changes.
